# 算命工具（产品名：blg必胜，可改名）MVP 设计文档

日期：2026-11-11
状态：待用户批准（已过实现者评审）

## 一、意图与背景

做一个面向真实用户的中文命理网页产品，第一版覆盖三种主流算命方法：**八字（四柱排盘）**、**易经六爻**、**塔罗牌**。紫微斗数与西方占星留作二期。

产品定位：真实排盘（真算法），不是随机文案娱乐向。核心信任点：**所有计算与用户输入均在浏览器本地完成，生辰数据不出设备、不入库**——这既是隐私承诺，也是产品卖点。

商业模式（一期不实现，但架构不堵死）：未来可能加账号、排盘历史、付费解锁深度解读。

## 二、目标 / 非目标 / 反目标

### 目标
1. 三个功能完整可用：八字排盘（含五行、十神、大运）、六爻起卦（含装卦、卦辞爻辞）、塔罗抽牌（含牌阵、正逆位解读）。
2. 排盘结果可生成分享卡片图（前端渲染长图）。
3. 移动端优先的响应式网页，中文界面。
4. 纯静态部署（Vercel 免费托管），无后端。

### 非目标（一期不做）
- 账号系统、数据库、任何服务端存储。
- 紫微斗数、西方占星。
- 真太阳时手动校正、地名→经纬度换算（一期用 UTC+8 平太阳时）。
- 付费/广告。

### 反目标（出现即为失败）
- 用户生辰被发送到任何服务器（包括埋点里带上生辰字段）。
- 排盘结果明显错误（如节气边界日期排错月柱）——命理产品排错盘等于产品死刑。
- 页面不可用时长超过必要的加载时间（纯静态，必须秒开）。

## 三、约束

- Windows 开发环境；工作目录 `E:\默认项目`。
- 命理算法正确性优先于功能数量：宁可少一个功能，不排错盘。
- 解读文案量大于代码量，文案以数据文件形式与逻辑分离。

## 四、技术选型（已定部分）

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 框架 | Next.js（App Router，`output: 'export'` 纯静态导出） | SEO 对获客关键（"八字排盘"等搜索词），静态导出仍可部署 Vercel |
| 样式 | Tailwind CSS | 移动端响应式开发快 |
| 历法引擎 | `lunar-typescript`（同作者 TS 版，自带类型定义） | 覆盖公历↔农历、干支、节气；八字 API（藏干/纳音/十神/大运）已实测可用且节气边界正确；注意其为全量包，需按页动态 import 懒加载 |
| 语言 | TypeScript | 排盘算法数据结构复杂，需要类型保护 |
| 塔罗牌面 | 1909 年公版韦特塔罗（Rider-Waite，公有领域）图像 | 免费可用、观感专业；图片懒加载控制体积 |
| 分享图 | `html-to-image`（DOM→canvas→PNG） | 纯前端，无服务器渲染；iOS Safari 需真机验证，预留时间 |
| 随机源 | `crypto.getRandomValues` | 掷币/抽牌用真随机，强化产品可信度 |
| 部署 | Vercel（静态） | 免费托管 + 自动 HTTPS |

架构要求：**计算层（`lib/`）与界面层（`app/`、`components/`）严格分离**。计算层不 import 任何 React，纯函数 + 数据文件，保证未来加后端时原样复用。文案全部放 `data/` 目录的独立文件。

## 五、各功能设计

### 5.1 八字排盘
- 输入：公历年/月/日/时（时辰精确到 2 小时区间），性别。
- 流程：`lunar-typescript` 公历→干支历（注意节气边界决定月柱）→ 四柱八字 → 五行统计与旺衰 → 十神 → 大运排布（按性别顺逆排）。
- **子时流派（已定）**：采用主流排盘软件通行的「晚子时换日」规则——23:00 及以后出生按次日日柱排盘，页面注明口径。
- 输出：排盘表（四柱、藏干、十神、纳音）、五行雷达/条形图（内联 SVG，不引图表库）、大运时间轴（排 10 步）、一段基于五行旺衰组合生成的解读（规则式文案拼接，非 AI）。
- 明确降级：一期不做真太阳时、不做流年细节分析，页面注明"按北京时间平太阳时计算"。

### 5.2 易经六爻
- 起卦方式（一期两种）：
  1. 手动掷币：用户点击六次模拟三枚铜钱（正面数 2/3 加权随机），记录每次老阴/少阳/少阴/老阳。
  2. 时间起卦：以起卦时刻年月日时数取卦（梅花易数式），适合不会掷币的用户。
- 装卦：自行实现纳甲、六亲、世应算法（规则明确、可查证），本宫五行属性表 + 六十四卦爻辰纳甲表作为数据文件。
- 解读：卦名 + 卦辞 + 变爻爻辞（有变爻时），六亲世应标注。不给断语结论（避免惹麻烦），只呈现传统卦辞爻辞原文与标排。
- **多爻动取占法则（已定）**：采用朱熹《易学启蒙》变占法则（0 爻动取本卦卦辞、1 爻动取动爻爻辞、2 爻动以上爻辞为主兼参……按通行规则实现），页面注明「采用朱熹变占法」。
- **时间起卦算法（已定）**：梅花易数式——农历年支数、月数、日数取上卦，加时辰数取下卦与动爻，页面注明算法口径。
- **多爻动取占法则（已定）**：采用朱熹《易学启蒙》变占法则（0 爻动取本卦卦辞、1 爻动取动爻爻辞、2 爻动以上爻辞为主兼参……按通行规则实现），页面注明「采用朱熹变占法」。
- **时间起卦算法（已定）**：梅花易数式——农历年支数、月数、日数取上卦，加时辰数取下卦与动爻，页面注明算法口径。
- 数据：64 卦结构数据（卦名、卦辞、六爻爻辞）约 2 万字，整理为 JSON；纳甲表调研 GitHub 开源数据集（如京房纳甲表）转换，需注明来源。

### 5.3 塔罗
- 78 张牌（22 大阿尔卡那 + 56 小阿尔卡那）数据文件：牌名、正位/逆位解读文案。
- 牌阵一期两种：三张牌阵（过去/现在/未来）、圣三角（MVP 从简，凯尔特十字二期）。
- 抽牌：洗牌（Fisher-Yates）+ 正逆位各 50% 随机；用户可点击"洗牌"动画参与仪式感。
- 输出：牌阵图示 + 每张牌位含义 + 牌义解读。

### 5.4 分享卡片
- 分享卡片：`html-to-image` 将结果区域渲染为 9:16 或 1:1 卡片图，含产品名水印，下载为 PNG。
- 卡片内不含用户输入的完整生辰（默认隐去年份，可开关显示完整日期）。**隐私口径（已定）**：开关仅控制分享图上的展示，生辰数据本身任何情况下都不离开浏览器；about 页与页脚注明这一点。

## 七、留给实现者的开放点

- 八字解读的规则文案体系（五行组合→文案映射的粒度）由实现者按文案数据实际整理情况定，原则：宁缺毋滥，没有把握的组合宁可只显示数据不给解读。
- 六爻纳甲表与 64 卦数据文件的整理方式（手工整理 vs 从开源数据集转换）由实现者调研后定，需给出数据来源。
- 视觉与 UI 设计：使用 `ui-ux-pro-max` 与 `ui-styling` 两个技能进行风格检索与实现（用户指定）。先出两版风格供用户挑选，再落地。
- 分享图字体：只用系统字体栈，规避 `html-to-image` 对 webfont 内嵌的兼容问题。
- 六爻装卦（纳甲/世应/六亲）为自实现模块，工期比原估偏紧，里程碑 4 预留缓冲。
- 塔罗视觉（已定）：采用 1909 年公版韦特塔罗图像（公有领域），78 张牌图懒加载。
- 塔罗解读文案：MVP 由实现者基于通行牌义撰写（每牌正逆位各一段，共 156 段），宁缺毋滥；后续可扩充或替换。
- 免责声明文案需实现者起草并放显眼位置。

## 八、产品名（已定：blg必胜，可改名）

产品名定为 **blg必胜**。要求**单点配置**：全站出现的名称（页面标题、SEO meta、分享卡水印、页脚、about 页）统一从一个站点配置常量读取（如 `config/site.ts` 的 `SITE_NAME`），任何组件不得硬编码名称字符串，保证改名只改一处。
