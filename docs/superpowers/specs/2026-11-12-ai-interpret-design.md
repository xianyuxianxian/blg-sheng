# AI 解读功能（短设计）

日期：2026-11-12
状态：已批准（用户确认方案 C + 隐私口径）

## 意图

三个功能（八字/六爻/塔罗）目前只给排盘数据和静态文案，缺"结合所问之事的白话解读"。接入公开 LLM API 生成动态解读。~~用户已确认：智谱 GLM-4-Flash（免费档）为默认模型。~~ 实现期改为讯飞星火 MaaS `spark-x2.5-1.7b`（见配置节）。

## 已定决策（用户拍板）

1. **交互形态 = 方案 C**：预设事项类别（下拉：事业/感情/财运/健康/学业/出行…）+ 可选一句话自定义补充框。
2. **隐私口径**：只发排盘结果（干支/卦象/五行/牌面，不含任何明文生辰年月日）；用户主动点击"AI 解读"才发送；about 页补充说明该口径。
3. **覆盖范围**：三个功能都加，同一接口、不同 prompt 模板。

## 架构

```
浏览器（排盘结果 + 事项 + 补充语）
   → POST /api/interpret（Vercel/Next API Route，key 在环境变量）
   → 调 GLM-4-Flash（OpenAI 兼容接口，流式）
   → SSE 流式返回 → 前端逐字渲染
```

- **必须有服务端**（API key 不能进前端包）。用 Next.js 的 App Router Route Handler（`app/api/interpret/route.ts`），同一仓库部署，Vercel Hobby 免费额度覆盖。
- 纯静态导出（`output: 'export'`）与 API Route 冲突 → 移除 `output: 'export'`，改 Vercel 常规部署（静态页自动 SSG + 一个 serverless function）。部署说明同步更新。
- Prompt 模板：系统提示写死安全护栏（不构成医疗/投资/法律建议、不诊断、末尾固定免责句、字号口径"仅供参考娱乐"）；用户内容 = 排盘结果 JSON（服务端从入参白名单重建，不透传自由文本到模型上下文）+ 事项类别 + 可选补充语（限 100 字，服务端截断）。
- **服务端白名单重建**：前端传 `type: 'bazi' | 'liuyao' | 'tarot'` + 最小排盘数据（如四柱干支字符串数组、卦名+动爻+六亲、牌名+正逆位），服务端校验形状（zod）后组装 prompt——防伪造/注入（用户补充语作为"用户所述所问"隔离在 user role，不进 system）。
- 降级：API 失败/超时（20s）→ 前端显示"解读服务暂不可用"提示，不影响排盘本体。
- 配置：`ZHIPU_API_KEY`（环境变量名沿用，实际存放讯飞 MaaS 的 key）、`AI_BASE_URL`（默认 `https://maas-api.cn-huabei-1.xf-yun.com/v2`，讯飞星火 MaaS，OpenAI 兼容 SSE）、`AI_MODEL`（默认 `spark-x2.5-1.7b`）环境变量；无 key 时按钮显示"未配置解读服务"。
  > 2026-11-12 controller 裁决：默认模型/端点由早先的智谱 GLM-4-Flash 改为讯飞星火 MaaS（实测可用）；端点仍属 OpenAI 兼容，换 DeepSeek 等只需覆盖这两个变量。该模型为推理型，`delta` 含 `reasoning_content`，服务端只透传 `delta.content`。

## 目标 / 非目标 / 反目标

- 目标：三页各一个"AI 解读"区块（类别下拉 + 补充框 + 按钮 + 流式渲染区）。
- 非目标：多轮对话、历史记录、账号、付费、流式打字机以外的 UI 花活。
- 反目标：API key 泄露到前端包；明文生辰出设备；AI 输出被当作确定性结论呈现（必须带免责标注）。
